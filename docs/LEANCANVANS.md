# 린 캔버스(Lean Canvas) — 모임 매니저 MVP

> 작성 기준: [PRD.md](./PRD.md)
> ※ 1~9번은 Running Lean에서 제시한 작성 순서이며, 아래 표기 순서는 참고 이미지의 배치(문제 → 해결책 → 가치제안 → 경쟁우위 → 고객세그먼트 / 주요지표 → 채널 / 비용구조 → 수익흐름)를 따른다.

---

## ① 문제 (Problem)

- 카카오톡 공지가 대화에 묻혀 참여자가 못 보고 놓침
- 참여/불참 취합을 단톡방 답장 + 수기 집계로 처리해 누락·중복 발생
- 카풀 매칭이 단톡방 텍스트로만 이루어져 정보가 흩어지고 매칭이 누락됨
- 비용 정산을 엑셀 + 수기 계산으로 처리해 미납자 추적이 어려움

**기존 대안**: 카카오톡 단톡방 공지 + 수기 참여자 취합 + 엑셀 정산

---

## ④ 해결책 (Solution)

| 문제                            | 해결책                                                   | 관련 기능  |
| ------------------------------- | -------------------------------------------------------- | ---------- |
| 공지가 묻힘                     | 모임/회차 단위 공지, 상단 고정 노출                      | F003       |
| 참여 취합 수기 처리             | 참석/불참/미정 RSVP + 정원 초과 시 자동 대기열/승격      | F004       |
| 카풀 매칭 누락                  | 운전/탑승 등록 게시판, 좌석 마감 시 모집완료 표시        | F006       |
| 정산 수기 계산·미납 추적 어려움 | 비용 등록 → 참석 확정 인원 기준 N빵 자동 계산, 완납 체크 | F007, F008 |
| 카톡 초대 대체 진입 수단 부재   | 모임별 초대 링크/코드 발급 및 합류 처리                  | F002       |

## ③ 가치 제안 (Unique Value Proposition)

> **정기 모임 운영에 필요한 공지·참여·카풀·정산을 한 곳에서**
> 단톡방과 엑셀에 흩어져 있던 주최자의 반복 업무를 하나의 흐름으로 통합한다.

---

## ⑤ 경쟁우위 (Unfair Advantage)

- 공지·RSVP·카풀·정산을 **하나의 회차(event) 데이터 모델**로 엮은 올인원 흐름 — 개별 도구(설문폼, 정산 앱 등) 조합 대비 전환 비용이 낮음
- Supabase 기반 인증·DB·RLS 인프라가 이미 구축되어 있어 기능 확장 속도가 빠름
- ※ MVP 단계에서는 검증되지 않은 항목으로, 실사용 피드백을 통해 방어 가능한 우위(예: 특정 종목 커뮤니티와의 관계, 데이터 축적)를 추후 구체화해야 함

---

## ② 고객 세그먼트 (Customer Segments)

- **주최자**: 수영·헬스·러닝 등 정기 모임(동호회)을 운영하며 현재 카카오톡+엑셀+수기 정산으로 관리 중인 사람
- **멤버**: 초대 링크를 통해 합류해 회차별로 참석 여부를 응답하고 비용을 분담하는 참여자

**얼리어답터**: 10~30명 규모의 소규모 동호회 중, 매주/격주 정기 일정과 회차별 비용 정산이 반복적으로 발생하는 모임 주최자

---

## ⑧ 주요 지표 (Key Metrics)

- 생성된 모임 수 / 그중 활성 모임(최근 4주 내 회차 존재) 비율
- 회차별 RSVP 응답률(정원 대비 응답자 수)
- 초대 링크를 통한 신규 합류 멤버 수
- 정산 완납률 및 완납까지 걸리는 평균 시간
- 회차 반복 참여율(재방문율)

---

## ⑨ 채널 (Channels)

- 초대 링크 공유(기존 카카오톡 단톡방, 문자 등 사용자의 기존 채널을 통한 바이럴)
- 동호회 커뮤니티(네이버 카페, 당근 모임 등)를 통한 초기 유입
- 지인 기반 입소문(주최자 → 다른 모임 주최자)

---

## ⑦ 비용 구조 (Cost Structure)

- 개발 인건비(초기 MVP 개발 시간)
- Vercel 호스팅 비용
- Supabase 사용료(DB/Auth)
- 도메인 비용

---

## ⑥ 수익 흐름 (Revenue Stream)

> PRD상 실제 결제/PG 연동은 **MVP 이후 기능**으로 명시적으로 제외되어 있어, MVP 단계의 수익 모델은 미확정이다.

- MVP 단계: 무료 제공, 사용성·리텐션 검증에 집중
- 향후 검토 후보(검증 전 가설 단계):
  - 모임 개수/멤버 정원 제한 후 유료 플랜(Freemium)
  - 정산 기능 고도화(실결제 연동) 시 거래 수수료
